# 漫画创作产品需求

## 背景与第一性原理

作者持续积累的作品和判断，比某次生成的文字或界面存活更久。外部Agent擅长理解和生成，固定引用、版本、范围及文件处理适合确定性软件。重复要求模型重建结构会增加上下文和等待，但本产品不承诺固定token节省比例。

把故事组织为页、格、阅读顺序与对白，关联实际图像并导出可阅读漫画。 需要长期专业状态和可视化审阅，适合作为按需安装的插件；核心只持有通用创作事实。

## 用户与目标

小说作者、编剧、漫画作者及音频创作者通过现有Agent对话完成准备和操作，回来检查实际成果。作者可直接编辑，但不必手工重复录入已说过的信息。

## 首版完整范围

页面、分格、气泡、图像固定来源、局部意见；固定读取、增量维护、检查、比较、可恢复写入、JSON/Markdown/HTML报告、专业成果导出、包内Skill及同连接热发现。

完整流程：读取故事→页格规划→人物与图像职责→关联实际图像→气泡排版→阅读检查→区域意见→局部换图→固定交付。

## 边界与非目标

漫画工程作为当前作品的专业成果，不新增宿主作品类型。分格和气泡使用规范化坐标，页面保存明确尺寸及左右阅读方向。示意格不冒充完成画面；图像只消费当前作品固定PNG/JPEG来源。HTML内嵌图像离线可读，未配图和越界单独检查，导出不表示作者认可。

不复制宿主正文、正式设定或版本库，不建设聊天和多Agent调度，不含发布、投放和运营。专业状态和候选不等于采纳或定稿。
